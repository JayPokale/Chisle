Caveman version:

Pool = collection of open DB connections reused across requests.

Without pool: each request opens connection → handshake overhead → closes after. Repeated per request = slow, expensive.

With pool: connections stay open, waiting. Request gets one from pool, uses it, returns it. Next request reuses same connection. No handshake per request.

Why helps:
- Skip connection handshake overhead (auth, negotiation, SSL/TLS)
- Reuse existing connections = fast
- Limit max connections (prevent resource exhaustion)
- Handle spikes: queued requests wait for available connection, not fail

Typical flow:
1. App starts → pool creates N connections (default 5-10)
2. Request needs DB → pool gives available connection
3. Request uses it → returns to pool
4. Next request reuses same connection
5. If all busy → queue request or timeout

Simple benefit: 100 requests with pool = reuse ~10 connections. Without pool = open 100 connections = 100x overhead + 100x auth.
