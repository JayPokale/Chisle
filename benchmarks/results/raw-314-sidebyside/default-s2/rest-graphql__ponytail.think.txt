Let me think about the core tradeoffs:

**REST:**
- Pros: Simple, well-understood, caching friendly (HTTP caching works well), easy to version, good tooling/ecosystem
- Cons: Over-fetching data, under-fetching data (need multiple requests), versioning overhead

**GraphQL:**
- Pros: Precise data fetching (client specifies exactly what it needs), single query endpoint, strongly typed schema, good for complex/interconnected data
- Cons: Complexity for simple cases, caching is harder (single POST endpoint), steeper learning curve, query complexity/DOS attack surface, server-side complexity

For a new API, the choice depends on:
- Complexity of data relationships
- Diversity of clients with different data needs
- Whether over/under-fetching is a real problem
- Team expertise
- Performance requirements
