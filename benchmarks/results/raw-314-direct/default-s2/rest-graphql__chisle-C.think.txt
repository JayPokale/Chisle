Let me think about the main tradeoffs:

**REST:**
- Pros: simple, cacheable, standardized, easy to understand, single endpoint per resource
- Cons: over/under fetching, multiple round trips, versioning headaches, rigid schema

**GraphQL:**
- Pros: precise data fetching (no over/under), single query, flexible, schema-driven
- Cons: complex to implement, N+1 queries, harder to cache, steeper learning curve, overkill for simple APIs, monitoring/debugging harder

Main tradeoffs:
1. Simplicity vs precision - REST is simpler, GraphQL is more precise but complex
2. Caching - REST benefits from HTTP caching, GraphQL doesn't play well with it
3. Developer experience - REST familiar, GraphQL has learning curve but powerful
4. Complexity - REST simpler server-side, GraphQL complex server-side
5. Payload size - GraphQL gets exact fields, REST may over/under fetch
