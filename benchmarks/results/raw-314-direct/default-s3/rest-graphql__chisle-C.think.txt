The main tradeoffs:

REST:
- Simpler to build and cache (HTTP semantics)
- Each resource has a fixed shape (over/under-fetching)
- Easier to debug (standard HTTP tools)
- Stateless, well-understood patterns
- Multiple requests for related data

GraphQL:
- Client specifies exact fields needed (solves over/under-fetching)
- Single query for related data (N+1 problem if not careful)
- More complex to implement (resolver logic, caching harder)
- Steeper learning curve
- Better for mobile/varied clients

Key decision point: Does the client need flexibility in what fields it fetches?
