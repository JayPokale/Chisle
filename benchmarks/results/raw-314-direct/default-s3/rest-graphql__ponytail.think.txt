Let me think about the core tradeoffs:

REST:
- Simple, well-understood, cacheable via HTTP
- Overfetching/underfetching data
- Multiple requests for related data
- Stateless, decoupled from frontend

GraphQL:
- Query exactly what you need
- Single request for complex data
- Steeper learning curve, more complex backend
- Harder to cache (usually POST)
- More upfront schema design work

The main tradeoff is simplicity vs precision. REST is simpler to build and deploy, GraphQL gives clients more power but costs more backend complexity.

For a new API, it depends on:
1. How complex are the data relationships?
2. How many different client shapes (mobile, web, different platforms)?
3. Team familiarity?
4. Performance requirements?
