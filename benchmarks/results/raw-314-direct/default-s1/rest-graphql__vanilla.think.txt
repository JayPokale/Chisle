Let me think about the core tradeoffs:
- REST: simpler to implement and cache, URL-based semantics are familiar, but clients often over-fetch or under-fetch data
- GraphQL: clients get exactly the data they need, but adds complexity on the server, harder to cache, steeper learning curve

For a NEW API, the tradeoff question is: do you value simplicity/speed-to-market, or do you value perfect data efficiency for clients?

Main recommendation: REST for most cases unless you have many diverse clients with varying data needs.

Main tradeoff: REST is easier to build and deploy but clients may waste bandwidth; GraphQL eliminates over/under-fetching but adds server-side complexity and HTTP caching challenges.
