Let me write this in chisle mode:

REST: HTTP verbs + status codes, cacheable via standard headers, URLs are endpoints. Downsides: N+1 requests for related data (get user → get posts → get comments per post), over-fetching (API returns fields you don't need). Upsides: CDNs work, simple load balancing, browser debugging, massive ecosystem.

GraphQL: Single request for exactly the fields you need. Client specifies shape. Downside: HTTP caching nearly useless (most requests are POST with bodies), query complexity can DoS your server, harder to debug, steeper learning curve. Upside: mobile clients love it (smaller payloads), reduces rounds trips.

Verdict depends on use case:
- Public API, heavy caching, simple queries → REST
- Mobile-first, complex/variable data needs, internal API → GraphQL
- Both → BFF pattern (public REST, internal GraphQL, or vice versa)
