Let me think through the pagination logic:

**Current broken logic:**
- Pages start at 0
- offset = page * pageSize + 1
- pageSize is typically, say, 10

For page 0: offset = 0 * 10 + 1 = 1
For page 1: offset = 1 * 10 + 1 = 11

So if pageSize = 10:
- Page 0 returns items 1-10 (skipping item 0, offset starts at 1)
- Page 1 returns items 11-20 (skips item 10 from the previous page)
- Page 2 returns items 21-30 (skips item 20 from the previous page)

The issue: The `+ 1` in the offset calculation shifts everything by 1 and also causes the skip. Let me trace it:

If we have items indexed 0-99 and pageSize=10:

Correct pagination should be:
- Page 0: offset = 0 * 10 = 0, fetch items 0-9
- Page 1: offset = 1 * 10 = 10, fetch items 10-19
- Page 2: offset = 2 * 10 = 20, fetch items 20-29

But with the broken formula (offset = page * pageSize + 1):
- Page 0: offset = 0 * 10 + 1 = 1, fetches items 1-10 (skips item 0)
- Page 1: offset = 1 * 10 + 1 = 11, fetches items 11-20 (skips item 10 which was on page 0)
- Page 2: offset = 2 * 10 + 1 = 21, fetches items 21-30 (skips item 20)
The root cause is the stray `+ 1` in the offset formula, which shifts every page's start by one. That makes page 0 skip item 0 and every later page drop the last item of the page before it. Removing it so the offset is just `page * pageSize` fixes both problems.
